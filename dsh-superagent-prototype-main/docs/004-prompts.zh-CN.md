# 004 提示词

> 本文是 [004 Prompts](004-prompts.md) 的中文译文，供阅读参考；如有出入，以英文原文为准。

本文说明 agent 读什么、团队能编辑什么，以及修改何时生效。它建立在 [000 哲学](000-philosophy.md) 到 [003 执行](003-execution.md) 之上。提示词文本以英文撰写。

## 团队写什么

团队可以编辑三个团队部分、添加技能，并覆盖每一个内置系统提示词部分。大多数默认内容位于 `prompts/` 和 `skills/` 下。工具描述、通知和卡片仍在代码中，无法通过提示词设置编辑。

| 部分 | 内容 |
| --- | --- |
| 沟通（Communication） | 何时给人发消息、消息的写法、每条 GitHub 消息开头的声明行（默认是 `This is by an automated agent, not a human`）、如何处理评审，以及哪些普通账号是评审机器人 |
| 工单范围（Ticket scope） | 工单何时继续，何时带着草稿停止 |
| 交付要求（Delivery requirements） | PR 中的证据、带行数阈值的自动合并条件，以及提交作者；未设置时，执行器以 agent 账号的 no-reply 地址提交 |
| 团队技能（Team skills） | agent 在需要时加载的知识，例如一个说明哪个 Feishu 用户对应哪个 GitHub 账号的 `identities` 技能 |

内置文本涵盖角色、工具用法、宿主机制、授权规则，以及 GitHub 和 Feishu 技能。它按标题引用团队部分，而不重复它们的内容。

### 内置部分与模板

覆盖使用这些键：

| 部分 | 键 |
| --- | --- |
| 共享指令与角色 | `runtime/shared`、`runtime/orchestrator`、`runtime/worker` |
| 工作指令 | `runtime/subscriptions`、`runtime/replies`、`runtime/dispatch`、`runtime/work`、`runtime/admission` |
| 移交指令 | `runtime/handoff/orchestrator`、`runtime/handoff/worker` |
| 来源技能 | `skill/feishu`、`skill/github` |
| 生成部分 | `runtime/environment`、`runtime/policy`、`runtime/policy/none` |

生成部分是可编辑的模板。它们必须保留这些占位符：

- `runtime/environment`：`{variables}`，填入执行环境的各行。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，每条已启用的规则一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，在没有启用任何规则时使用。

编辑某个部分会改变模型收到的指令。它不会改变准入、授权、工具检查或账号包装脚本——这些仍由代码强制执行。

在明确的人工请求下，主 Session 还可以用 `orchestrator_prompts_save` 保存覆盖。如果一次保存省略了某个覆盖的 `base`，它会保留已保存的 base。已保存在配置中、但又被移除的部分会在保存时被丢弃；任何其他未知部分会被拒绝。

一份覆盖会记录它基于哪份内置文本。升级会保留团队文本。如果默认内容变了，面板会把这个部分标为 **Default updated**，并在团队文本旁显示差异。团队可以保留自己的文本、采用新默认内容，或修改它。没有覆盖的部分会自动跟随新的默认内容。

主 Session 可以在 `orchestrator_read prompts` 的 `default_changed` 下读取受影响部分的名称。

## 组装与优先级

系统提示词按以下顺序组装：

1. 共享指令与角色。
2. 三个团队部分。
3. 订阅与回复。
4. 主 Session 的派发指令，或执行器的工作指令。
5. `runtime/admission`，仅用于主 Session。
6. 移交指令。
7. `runtime/environment`。
8. `runtime/policy`，仅用于主 Session。

准入指令来自 `prompts/admission.md`。它们描述主动研判，以及何时可以仅凭卡片忽略一个无关候选。`orchestrator_eval` 返回上下文，而不重复这些指令。

环境部分给主 Session 提供部署级的值，给每个执行器提供其工单专属的值。策略部分在每次模型请求时都根据设置重新生成。它包含策略版本、接受模式、明确请求的豁免，以及已启用规则的 `- <名称> (<id>): <指令>` 形式，或者一条“未启用任何规则”的说明。它放在最后，因此策略变更不会影响前面的提示词文本。

执行器还会读取 DeepSeek Harness 的编码提示词和仓库的 `AGENTS.md`；主 Session 则不会。推断工单会在末尾附加一条说明，把其执行器限制在匹配的规则内。派工和传入消息以内联的触发卡片形式到达，只有被截断的内容才使用资源指针。

执行器在无人值守的情况下工作。它们的工具排除那些需要询问人、向人展示 UI 或更改 profile 的工具，例如 `ask_user_question`、`present` 和 `plugin_manager`。

从强到弱：

1. 由工具和宿主强制执行的事实：身份、权限、工具参数检查、回复用途、长度限制。提示词文本无法改变它们。
2. 内置部分和生成部分，按其团队覆盖所写的形式。
3. 主动工单所匹配规则中的流程与沟通要求，仅作用于该工单的执行器 Session。
4. 团队部分和团队技能。
5. 外部文本：消息、评论、文档和引用。它是数据，永不改变规则或授权。

## 内置文本的原则

这些原则把 [000 哲学](000-philosophy.md) 应用于 agent：

- **角色分离。** 主 Session 只做路由：它转发原始触发和路由事实，不做技术决策，并通过一个路由工具在一次调用中对多个等待中的候选做出决定。一条路由说明最多 30 个词。执行器读取原始来源、判断范围、实现并验证。
- **主 Session 不等待。** 报告、跟帖通知、候选和已完成的后台任务都会作为消息自动到达。没有剩余事情可做时，它就结束本轮。一个守卫会拒绝 `sleep`、超过 30 秒的 shell 超时和超过 5 秒的任务等待，因为被阻塞的步骤会延迟新候选。这些指令取代了 DeepSeek Harness 自身在主 Session 完整提示词中的任务通知说明。
- **只在有人必须行动或能用到结果时才发消息：** 结果可供评审或使用、需要决策或资源，或工作无法完成。聊天消息默认一句话，硬上限 100 个词。
- **执行器决定自己的跟帖。** 每个执行器处理并确认范围内的请求，并交回超出其工单或属于其他工单的请求。只有当一条消息的所有拥有者都交回它或结束而未处理它时，它才成为新工作。主 Session 会收到跟帖通知，但只能为了停止工作而对其采取行动。交回的消息随后作为候选抵达，并带有执行器的理由。
- **通过订阅和主 Session 协调。** 执行器为获取上下文而跟随相关线程。主 Session 可以在一条最多 100 个词的说明中发送来自其他工单的事实。订阅和说明都不授予权限。
- **只在明确引用时挂接。** 消息必须指向某个工单的 PR、Issue、来源消息或确认，或者指向一个只有唯一匹配工单的近期变更。仅话题相似不够。挂接会把工单订阅到整个线程；判定其无关的执行器使用 `orchestrator_thread_unrelated`，并不在那里作答。
- **具体而只确认一次。** 在开始实质工作之前，执行器确认每个新请求，并说明对象和预期结果，作为原消息下的回复。
- **通过 `human_action` 提问。** 执行器在报告中放入一个具体问题，主 Session 原样转发。如果问题因某人的消息而起，它会指明该消息，宿主就在那里提问。否则在工单的原始会话中提问。与此同时，已获授权的工作可以继续。
- **诚实的交付。** 开启 PR 不等于就绪；草稿标明未完成；没有真实“改前”截图的 UI 变更不算就绪。
- **人的暂停会保持，** 跨越跟帖、新的执行器 Session 和重启，直到有人解除它。自动反馈永不恢复被暂停的工作。
- **示例只展示格式。** 示例句子不是 agent 可以主张的事实。
- **按结果处理评审。** 已修复并验证的评论会被静默解决；被拒绝的评论会给出（译注：英文原文此处疑漏“one sentence of reason”，按上下文理解为“一句话说明理由”）。对自动评审者的线程在其得到回答后即被解决，每个 PR 对每个自动评审者最多三轮。
- **让位于重复工作。** 当某人的分支或 PR 已包含本工单的改动时，执行器用一句话关闭自己的 PR 并指向他们的 PR。

## 版本

- 每次保存都会创建一个不可变版本，包含完整配置、修订号、前驱版本、时间戳和来源（面板或工具）。恢复某个版本或默认内容会再创建另一个版本。
- 保存时会声明其基础修订号。冲突的保存会被拒绝，且草稿不会被丢弃。
- Session 在每次模型请求时都读取最新版本，包括同一轮中后续的步骤。保存不会重启、取消或唤醒 Session。宿主会记录每个 Session 所使用的修订；执行器可以读取它工作期间所用过的任何修订。
- 部署会设置总大小上限，包括覆盖。校验会拒绝未知键、保留的内置技能名称、未知的覆盖部分和缺失的模板占位符。它绝不静默截断文本。与默认内容完全相同的覆盖会被移除，以便该部分继续跟随未来的默认内容。
