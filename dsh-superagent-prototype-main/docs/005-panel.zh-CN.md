# 005 面板

> 本文是 [005 Panel](005-panel.md) 的中文译文，供阅读参考；如有出入，以英文原文为准。

在 DeepSeek Harness Web 侧边栏打开 **Superagent** 来监督 agent。面板优先展示需要人处理的工作，其次是系统健康和历史。本文建立在 [000 哲学](000-philosophy.md) 到 [004 提示词](004-prompts.md) 之上。

## 三个问题

打开面板会按以下顺序回答三个问题：

1. 现在有需要我处理的事情吗？
2. 系统是否健康、是否在做正确的事？
3. 某一件工作的历史是什么——从触发、经过评估到工单？

## 标签页

标签页遵循工作流：**总览**、**来源**、**触发**、**评估**、**执行** 和 **设置**。在仓库和账号设置成功之前，总览会显示缺少什么，并链接到相应的设置。

| 标签页 | 显示内容 |
| --- | --- |
| 总览 | 需要处理的工单、系统问题、过去 24 小时的活动计数，以及执行器负载。每个区块都链接到其详情页 |
| 来源 | 来源状态、设置问题和非零计数。被过滤的触发和被丢弃的消息覆盖与总览相同的 24 小时窗口 |
| 触发 | 按“已订阅”“评估中”“24 小时内的新触发”或“所有线程”过滤的线程。每个线程按最新在前显示其触发、决定和订阅 |
| 评估 | 决定及其理由和匹配的规则 |
| 执行 | 执行器状态、暂停处理，以及按“打开”“待启动”“执行中”“等待触发”或“已结束”过滤的工单。工单详情显示操作、授权、等待中的输入、订阅和派工 |
| 设置 | 来源、评估、执行、提示词和部署。每个分组都包含其保存历史 |

### 阅读单条记录

被丢弃的消息会链接到其工单，若没有工单则链接到其线程。来源页面会说明是该会话已消失，还是来源不再监听它。

仍被执行器拥有的人工跟帖会标为 **已投递给工单**，且不经过评估。线程还会显示交回的理由和仅作上下文的订阅。**重新评估** 可以把该跟帖送进评估，或重试一个没有生效判断的触发：被来源过滤的、评估结果为未完成的，或已投递但在其后既没有非停止决定也没有执行器确认的消息。

工单详情显示原始触发、决定及理由、范围和策略版本。派工和次要细节折叠在即时操作之下。**重试** 适用于输入投递失败，或在受阻/失败报告之后等待人的工单。已结束的工单会显示 **PR 已合并** 或 **被人停止** 等结果。

## 设置分组

- **来源：** 每个来源一张卡片，含其开关、字段和已核实的账号事实。GitHub 还为新 Issue、PR、评论和默认分支 CI 提供接收全部开关。轮询和读取限制位于“高级”下。
- **评估：** 策略版本和规则，其后是 **每个来源** 和评估设置。每个来源的标签页包含其允许名单、成员同步、准入表和机器人名单。同步在启动时运行，也会在 **立即同步** 时运行。准入表区分接收范围、发送者成员关系以及消息是否指向 agent。评估设置选择接受模式、超时和研判模型。
- **执行：** worker 模型、并发数、目录根、prepare 命令和被禁止的命令。点击一个可用变量会把它插入 prepare 命令。
- **提示词：** **编辑** 可修改团队部分、内置部分和技能。**完整提示词** 显示组装后的文本，并与已保存的文本或默认内容比较。**历史** 列出各版本。被编辑过的内置部分会标记为已更改，并可以重置；模板会列出所需的占位符。

  一次改变了被覆盖默认内容的升级会把它标为 **Default updated** (默认内容已更新)。面板会在团队文本之上比较新旧默认内容。如果旧默认内容未被记录，则改为把团队文本与新默认内容比较。可选择 **保留我的文本** 或 **使用新的默认内容**。已移除部分的覆盖会列在标签栏下方，并在下次保存时被丢弃。
- **部署：** 启动问题（含 **重新检查**）、状态目录和机器限制。已保存的限制无需重启即可生效。DeepSeek Harness 的插件管理器会展示同一页面。

## 搜索

页眉搜索可按文本、id、Feishu 消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。原消息中缺少的 Feishu 链接，只有宿主在当前进程生命周期内读取过它之后才可被搜索到。

搜索还可以按 `#12` 或 GitHub URL 之类的引用查找线程，并按标题或匹配的线程查找工单。

## 原则

1. **聚焦重要的事情。** 每个元素都要回答三个问题之一，否则就被去掉。只有当数字会改变监督者的行为时，它才会出现。
2. **精确定义。** 分类具有可检查的定义，彼此互斥并覆盖所有情况，正如工单阶段那样。标签说明某一行在等谁、需要什么，而不是内部状态码。
3. **每个概念只有一处。** 来源状态属于“来源”；线程和触发属于“触发”；决定属于“评估”；工单属于“执行”。设置按其所配置的概念分组。总览概括这些页面并链接到它们，而不是变成另一个详情视图。
4. **领域结构。** 面板使用领域术语。内部标识符只出现在折叠的细节中，在可解析的地方用名称取代标识符。
5. **诚实的状态。** 计数等于它所链接列表的长度，且任何状态都不与其他事实矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须可操作；偶发的网络错误不算。需要人处理的行直接提供其操作。页面说明保持一句话，更多细节放在 (?) 提示框中。破坏性操作需要确认。
7. **一致的控件。** 使用 DeepSeek Harness 的设计令牌和控件行为。相同的信息在面板各处外观应当一致。每个设置区块只有一条保存栏，仅在存在更改、正在保存或保存失败时可见。
