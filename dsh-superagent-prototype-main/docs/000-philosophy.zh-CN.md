# 000 哲学

> 本文是 [000 Philosophy](000-philosophy.md) 的中文译文，供阅读参考；如有出入，以英文原文为准。

dsh-superagent 是一套框架，也是一种与 agent 协作的工作方式。其核心原则：

**尽可能少地占用人的注意力，尽可能多地交付价值。**

项目的每一个部分都以它消耗的注意力来衡量。一条消息、一个通知、一个提问、一项设置、一个面板元素、一段文档，都会消耗某个人的注意力；每一项都必须给出多于这份消耗的价值，否则就会被去掉。

## 对 agent 的要求

- **只在被请求时行动，或只在成文规则允许时行动。** 只有直接指向 agent、且来自团队允许的人（在允许名单上，或来自团队开放了请求的会话中的任何人）的请求才算数。没人要求的工作需要一条团队写下的规则，并且一开始只运行在仅记录“agent 本来会做什么”的模式下。
- **只在有人必须行动或能用到结果时发言。** 它对一个请求只确认一次，并说明将做什么。工作过程中它保持安静。结果就绪、需要决策或无法完成时才再次发言。消息要短，并回到提出请求的那个会话里。
- **一次只问一个具体问题，** 以结构化形式提出，让问题抵达对应的人，而不是埋在一份长报告里。
- **以影响面而不是投入量来决定何时停下。** 局部改动一直做到可评审的结果为止。需要设计决策的改动则带着明确的问题停下。
- **如实报告。** 草稿标明尚未完成，失败就报告为失败，绝不为了回避提问而绕过某个限制。

## 对设计的要求

- **概念要少。** 设计只有它自己的领域概念（如“来源”）及其具体实现（如 GitHub 和 Feishu）。一个业务需求要么成为其中之一的一个属性，要么成为 agent 遵循的提示词。设计不为此新增概念。
- **设置要少。** 当某个值几乎适用于所有团队时，用默认值取代设置项。团队用文字描述的行为属于提示词文本，不是设置项。
- **面板只显示需要人来处理的内容。** 它首先列出在等人处理的事项。健康状态不占位置。
- **文档按顺序阅读。** 每篇编号文档只建立在它之前的文档之上，因此读者永远不需要尚未介绍过的概念。

## 责任

agent 以团队每天都能看到的账号发评论、开工单和给人发消息。它发出的每一条消息都在消耗同事的注意力，这份责任由你承担。agent 的能力越强，运营者欠团队的谨慎就越多：

- **从窄开始。** 从一份很短的允许名单开始，并且主动工作只做记录。等“agent 本来会做什么”看起来正确之后，再放宽这两者。
- **为减少噪音而调优。** agent 吵闹时，把它的提示词改得更短更严，或者把它暂停。不要用更多消息来解释噪音。
- **不要用它制造信息量。** 批量开 PR、群发消息和无效忙碌，团队付出的代价大于所得。
- **为它说的话负责。** 读一读 agent 以你的名义发布的内容，错了就改提示词。

目标是：在正确的时间给出正确的帮助，其他任何时间什么都不给。
