# 技能（Skill）

> 技能是**教模型怎么做事**的知识文件。和扩展（extensions）不同：
> 扩展是给程序的代码钩子，技能是给模型看的 Markdown 说明。

---

## 为什么需要

有些知识只对特定任务有用——「这个项目的测试怎么写」「发布流程是什么」。
没有技能机制时，这些只能塞进系统提示词，**每条消息都在付费**。

技能把这件事变成按需加载：

```
平时：系统提示里只有   - write-tests：按本仓库约定写测试。（约 20 token）
需要时：模型调 use_skill → 拿到完整正文（可能是 2000 字）
```

实测一个 291 字的技能，目录只占 88 字——**省了 70%**。技能越长，省得越多。

---

## 怎么用

### 1. 放文件

两个位置，**项目级覆盖同名的用户级**：

| 位置 | 用途 |
| --- | --- |
| `<项目>/.opencoxswain/skills/` | 这个项目自己的约定 |
| `~/.opencoxswain/skills/` | 跨项目通用的习惯 |

两种布局都支持：

```
skills/
├── write-tests/
│   └── SKILL.md        ← 目录包（推荐，可以带附件）
└── release.md          ← 平铺文件（简单场景）
```

### 2. 写内容

```markdown
---
name: write-tests
description: 按本仓库约定写测试。用户要求加测试、补测试时使用。
when-to-use: 需要新增或修改测试文件时
---

# 写测试

本仓库用 node:test，不用 vitest。

## 约定

- 测试文件放 `src/test/*.test.ts`
- 断言用 `node:assert/strict`
- 每个测试名要说清守的是什么
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 否 | kebab-case；缺省用目录名 |
| `description` | 否 | **最重要的字段**——模型靠它判断要不要加载 |
| `when-to-use` | 否 | 进一步帮助模型判断时机 |

**没有 frontmatter 也能用**：名字取文件名，描述取正文第一个非标题行。

### 3. 生效

**立刻生效，不用重启**。每次派活时会重新扫一遍目录。

---

## 三条设计约束

### 目录只含名称和描述

正文永远不进目录。这是省 token 的前提，有测试守着
（`skills.test.ts` 断言「目录长度远小于正文」）。

### 描述要写清「什么时候用」

模型根据 `description` + `when-to-use` 决定要不要加载。
写成「测试相关」它不知道该不该用；写成「按本仓库约定写测试，
用户要求加测试时使用」它就懂了。

### 名字必须 kebab-case

`write-tests` ✅　`Write Tests` ❌　`write_tests` ❌

不合法的名字会被自动转换；转不出来的（比如 `***`）整个技能被跳过。

---

## 和扩展的区别

| | 扩展 | 技能 |
| --- | --- | --- |
| 给谁 | 程序 | 模型 |
| 写什么 | JS 代码 | Markdown |
| 能做什么 | 否决工具调用、观察事件 | 提供做事的知识 |
| 何时生效 | 每次工具调用 | 模型主动调用 |

技能**不能**绕过写域限制、跳过审批、改变验收——
它只是知识，不是权限。
