# 撤销设计

> 写于 2026-11-13
> 解决的问题：Agent 改了文件，用户想退回去——现在没有任何入口。

---

## 一、现状

| 已有 | 缺的 |
| --- | --- |
| 副作用台账记录每个动作（改了哪个文件、什么参数） | **改之前的内容没留** |
| 每个动作标记`可逆 / 不可逆` | 可逆的也没有"怎么撤"的数据 |
| 轨迹可展开看每一步 | 看完只能手动改回去 |

所以"撤销"不是加个按钮，是**先有数据基础**。

---

## 二、只做一件能真做好的事

撤销的范围可以很大（改文件、跑命令、发网络请求……），
但**只有"改文件"是能可靠撤销的**——只要留了原内容。

| 动作 | 能否撤销 | 为什么 |
| --- | --- | --- |
| 改文件 / 写文件 | ✅ 能 | 留了原内容就能写回 |
| 删会话 | ✅ 能 | 数据还在，改个标记 |
| 跑命令 | ❌ 做不到 | 你不知道那条命令到底改了什么 |
| 发网络请求 | ❌ 做不到 | 发出去收不回来 |
| git push | ⚠️ 部分 | 能 revert，但那是一次新提交 |

**所以第一版只做"撤销写文件"。** 其余的在界面上明确标"不可撤销"，
不给假承诺。

---

## 三、怎么留原内容

在 `write_file` / `edit_file` **执行前**，把原内容存进一个快照区：

```
~/.opencoxswain/snapshots/<sideEffectId>/<相对路径>
```

按副作用记录的 id 建目录，每个被改的文件存一份原始内容。

### 为什么不存进数据库

内容可能很大（几 MB 的日志）。SQLite 里存大文本会让数据库膨胀、
备份变慢。文件系统更合适，而且用户能直接看到。

### 为什么不存 git

不是所有项目都在 git 里；即使是，改到未跟踪文件也恢复不了。
**自带快照比依赖 git 可靠。**

---

## 四、撤销的边界（必须写清楚）

| 情况 | 行为 |
| --- | --- |
| 文件在撤销前又被改过 | **拒绝撤销**，告诉用户"这文件之后又被改过" |
| 原文件当时不存在（新建的） | 撤销 = 删掉这个新文件 |
| 快照丢了 | 明确说"找不到原始内容"，不假装成功 |
| 不可逆的动作 | 界面上标出来，不给撤销按钮 |

**第一条最要紧**：静默覆盖掉用户后来的修改，比不撤销更糟。

---

## 五、界面

### 入口

轨迹页里，每个可撤销的写操作旁边加一个"撤销"按钮。

### 撤销后

不删台账记录，而是**追加一条"已撤销"的记录**——
和"重试不删历史"是同一个原则：**事实不该被抹掉**。

---

## 六、不做的事

| 不做 | 理由 |
| --- | --- |
| 一键全部撤销 | 顺序错了会把文件改乱；逐个撤销才可控 |
| 撤销跑过的命令 | 做不到，不假装 |
| 撤销 git push | 那需要 revert 提交，是新动作不是撤销 |
| 自动备份所有文件 | 存储爆炸；只备份**被改的** |

---

## 七、验收标准

- [ ] 改了文件后，轨迹里出现"撤销"按钮
- [ ] 点撤销，文件内容回到改之前
- [ ] 新建的文件撤销后消失
- [ ] 文件被后续改过时，撤销被拒绝并说明原因
- [ ] 不可逆动作没有撤销按钮
- [ ] 撤销本身记进台账
