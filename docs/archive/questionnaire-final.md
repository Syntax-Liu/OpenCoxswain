## 2. 共用情境（受访者可见，所有题基于此）

> 想象电脑上有一个程序，你把一件事交给它，说清要什么。它会先把事情拆成几步列给你看。
>
> - 互不冲突的几步，可以由几个不同的「帮手」同时做；每个帮手在自己的地方干活，做完把结果交回来，再由它合到一起。帮手之间能不能看到彼此的过程，可以事先设定。
> - 每一步都会留下记录：改了什么、依据是什么、还有哪里没把握。
> - 有的地方需要你停下来确认；有的地方它自己先核一遍，只在没把握或需要你拍板时来找你。
> - 它只在你事先圈定的文件夹里工作；要动圈定范围以外的东西、要联网、要替你发消息，得再问你一次。
> - 某一步没做好，可以只重做那一步，也可以退回到更早的地方；已经发出去的消息、已经改过的外部系统，不一定能撤回。
> - 想让它多会一种活，可以装别人做好的，也可以自己写一段说明。

## 5. 结论怎么用（不要过度解读）

1. **先看 C1 + C3 + A5 三题**，它们决定产品是「总管」还是「验收器」。其余题都是修饰。
2. **并行度公式**：`可并行 worker 数 ≈ 每周可接受打断次数 ÷ （单任务平均验收节点数 × 每周任务数）`。用 C3 中位数、C1 分布、B1 选择比例估算；若 < 1.5，不做多员工。
3. **分组只做描述**：个人 / 小团队 / 企业各组的 C1、C3、E5 分布并列展示，不强行做显著性检验（样本 < 30 无意义）。
4. **声称偏好 ≠ 行为**：E5 的承诺阶梯权重大于 E4 的价格；A2 / A3 / A4 的行为题权重大于 B1 / C1 的假设题。
5. **允许结论是「不成立」**：若 H8、H9 同时不达标，正确动作是把产品收窄为「本地、可追溯、带验收留痕的单 agent 工具」，而不是继续做多员工。
