# TRAE 宝调研摘录（产品参照）

> 采集时间：2026-11-11。来源：TRAE 官方文档。
> 用途：作为 OpenCoxswain 四层结构的产品参照与设计印证。**不是要照抄，而是确认我们的判断。**

## 1. 两个角色（官方定义）

> **全局助理**：理解你的长期积累。它跨项目读取历史任务、对话和产物，梳理相关方案、约束与偏好，为新任务准备好起点，省去你反复介绍背景的时间。
>
> **项目助理**：负责当前项目的执行。它可以围绕一个具体的项目工作，掌握更完整、精确的项目上下文，拆解复杂需求，调度子任务并行推进，完成联调与汇总，把需要你判断的问题和最终成果带回来。

### 与我们四层结构的对应

| TRAE 宝 | 我们 | 说明 |
| --- | --- | --- |
| Supervisor | **B** | 跨项目视野，不执行 |
| Assistant | **C** | 项目的主人，调度Agent |
| （未单独命名） | **D** | TRAE 宝把子任务当作Assistant内部的调度单元；我们把它显式化为可对话的 D |

**差异（我们更进一层）**：TRAE 宝的子任务对用户不可直接对话；我们的 D 可以被用户直连追问。这与用户的设想一致。

## 2. 入口与交互

| 动作 | TRAE 宝的做法 | 我们的对应 |
| --- | --- | --- |
| 打开Supervisor | 点击左侧导航栏的 TRAE 宝 | B 入口 |
| 打开Assistant | 点击项目栏中的某个项目 → 打开"项目专属 · TRAE 宝" | C 入口（`openProject`） |
| 工作台 | 顶部悬浮卡片 → 右侧面板 | 待做（UI 阶段） |
| **回复指定消息** | 悬停消息 → 点"回复"图标 → 追加信息 | **我们的 `Inbox` + `turn` 表** |
| 打开原会话 | 任务列表点某任务 → "打开会话"看原始思考过程 | **我们的 Agent 会话历史**（已入库，UI 待做） |

### 关键印证：C 是"一项目一会话、长期常驻"

TRAE 宝的Assistant是**按项目打开的固定面板**，不是每次派活新建。这直接印证了我们的设计：

> 每个项目一个 `Session`，`assistantSessionId` 是锚点；同一路径永远得到同一个 C。

## 3. 并行与汇报

> 你也可以继续布置其他任务，无需等前一个结束。各个子任务的进度和结果会**先汇总到项目助理**，再由它整理出需要关注的问题、待定事项和交付产物。

这与用户要求的"谁先完成先汇报谁"方向一致（TRAE 宝是"先汇总到Assistant"，我们在此之上要求**每个 D 完成即报**，更及时）。

## 4. 记忆机制

| 维度 | TRAE 宝 |
| --- | --- |
| 类型 | 全局记忆 + 项目记忆 |
| 存储 | **本地 Markdown 文件**，不是向量库 |
| 全局位置 | `%userprofile%/.trae-cn/memory/user_profile.md` |
| 项目位置 | `%userprofile%/.trae-cn/memory/projects/{project_path}/project_memory.md` |
| 共享 | **不跨电脑**，纯本地 |
| 自动维护 | AI 识别有价值偏好自动创建/更新；也可用户明说"记住…" |
| **不保存** | 一次性/临时指令、模糊不确定的偏好、敏感信息（密码、隐私） |

### 与我们 legacy `packages/memory` 的对照

legacy 的设计**恰好吻合**：

| legacy 机制 | TRAE 宝对应 |
| --- | --- |
| `memory/` 下导出 Markdown 快照 | 本地 Markdown |
| 写入门槛：拒绝临时指令（"这次…"） | 不保存一次性指令 |
| 写入门槛：拒绝疑似密钥 | 不保存敏感信息 |
| 写入门槛：拒绝过短内容 | 不保存模糊偏好 |
| 必须带来源 | （TRAE 未明说，我们更严） |
| SQLite FTS5 + 中文二元组检索 | TRAE 靠文件 + 提炼 |

**结论**：记忆层可以直接复用 `packages/memory`，并把 TRAE 宝的"全局/项目两级 + 本地 Markdown"作为存储布局。

## 5. IM 通道

| 维度 | TRAE 宝 |
| --- | --- |
| 支持 | 飞书（智能体应用）、微信（ClawBot 插件） |
| 能力 | 单聊/群聊派活、补充信息、确认结果、停止任务、看产物 |
| 同步 | 单聊记录双向同步到 Agent 窗口；**群聊不同步** |
| 前提 | 桌面端必须运行且保持唤醒 |

与我们 legacy 的 `channels`（飞书 / Telegram）设计基本一致，后续 P6 阶段接入。

## 6. 对我们的四个直接启示

1. **C 必须一项目一常驻会话** —— TRAE 宝已验证，我们照做。✅ 已实现
2. **记忆用本地 Markdown + 写入门槛** —— 复用 `packages/memory`，按全局/项目两级布局。
3. **任务要能"打开原会话"** —— D 的会话历史必须完整保留，不能只存结论。✅ 已入库
4. **IM 是重要入口** —— 但群聊上下文不同步这个设计要抄：群聊里说的话不回流到 C 的主会话，避免污染。
