# OpenCoxswain 需求验证问卷 v2（可直接发放）

> 版本：2026-11-09
> 定位：验证「AI 总管 + 多员工 + 任务树 + 人工验收 + 插件化 + Windows 本地」这个形态是否成立，而不是测「想不想用」。
> 参考：腾讯元宝《项目可行性分析与问卷设计》重做版（2026-11）。本版保留其「机制具体、强制取舍」的优点，修正三处方法问题：
> 1. 原版全是假设题，易得「声称偏好」；本版先问**最近 30 天真实发生的事**，再问取舍。
> 2. 原版刻意不问身份；本版按需求方要求区分**个人开发者 / 小团队 / 企业**，但**不按身份分卷、不跳题**，只在分析时分组，保证可比性。
> 3. 原版只问月费；本版加**承诺阶梯**，测「从想用到付钱」的真实距离。

## 1. 开场白（受访者可见）

> 下面描述的是**一类工具的不同做法**，不是某一个真实产品，也没有标准答案。
> 无论你平时做什么、有没有用过类似工具，都可以回答；每题都有「说不清 / 没遇到过 / 以上都不」可选。
> 答案只做汇总统计，不识别个人，也不会用于推销。请按**你最近真实的工作情况**回答，而不是按「理论上应该怎样」。

## 2. 共用情境（受访者可见，所有题基于此）

> 想象电脑上有一个程序，你把一件事交给它，说清要什么。它会先把事情拆成几步列给你看。
>
> - 互不冲突的几步，可以由几个不同的「帮手」同时做；每个帮手在自己的地方干活，做完把结果交回来，再由它合到一起。
> - 帮手之间能不能看到彼此的过程，可以事先设定。
> - 每一步都会留下记录：改了什么、依据是什么、还有哪里没把握。
> - 有的地方需要你停下来确认；有的地方它自己先核一遍，只在没把握或需要你拍板时来找你。
> - 某一步没做好，可以只重做那一步，也可以退回到更早的地方；已经发出去的消息、已经改过的外部系统，不一定能撤回。
> - 它只在你事先圈定的文件夹里工作；要动圈定范围以外的东西，得再问你一次。
> - 你没吩咐、但它觉得另一件相关的事该做时，它可以选择提醒你、记下来不动、或者直接做掉。
> - 想让它多会一种活，可以装别人做好的，也可以自己写一段说明。

| H16 | 停用红线 | G1 | 高频词直接写成 v1 禁止项 |

## 5. 结论怎么用（不要过度解读）

1. **先看 C1 + C3 + A5 三题**，它们决定产品是「总管」还是「验收器」。其余题都是修饰。
2. **并行度公式**：`可并行 worker 数 ≈ 每周可接受打断次数 ÷ （单任务平均验收节点数 × 每周任务数）`。用 C3 中位数、C1 分布、B2 选择比例估算；若 < 1.5，不做多员工。
3. **分组只做描述**：个人 / 小团队 / 企业各组的 C1、C3、E6 分布并列展示，不强行做显著性检验（样本 < 30 无意义）。
4. **声称偏好 ≠ 行为**：E6 的承诺阶梯权重大于 E5 的价格；A2/A3/A4 的行为题权重大于 B2/C1 的假设题。
5. **允许结论是「不成立」**：若 H8、H9 同时不达标，正确动作是把产品收窄为「本地、可追溯、带验收留痕的单 agent 工具」，而不是继续做多员工。
