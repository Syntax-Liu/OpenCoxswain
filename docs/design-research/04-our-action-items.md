## P0 · 先做

### UD-01 · 状态呈现加"当前步骤" ✅ 已完成（`0d7700a`）

> **结果**：侧栏现在是 `● 登录页重构  修改 login.tsx  2分13秒`。
>
> 实现比预想简单——链路其实全都在，只是 `runner.ts` 收到工具调用后
> **只写库没广播**。补一个 `executor_step` 事件（300ms 节流）即可。
> 新增 `apps/runtime/src/executor/step.ts` 做「工具调用 → 人话」翻译。
>
> **关键设计**：拿不到文件路径就如实说"读取"，**绝不编造**。
> 15 条测试专门守这一条。

**为什么**

[03 A1](03-agent-ui-problems.md#a1--全程一个转圈用户以为卡死)：
本项目的状态数量够多（6 个），但只有一行文字。用户看到"执行中"但不知道**在做什么**。

原文结论：

> "命名当前步骤几乎不需要任何成本，并且会改变等待的时间。"

**现状**

```ts
// apps/web/src/state.ts:294
export const EXECUTOR_STATUS_LABEL = {
  starting: '启动中',
  running: '执行中',
  done: '已完成',
  failed: '未完成',
  cancelled: '已取消',
  handback: '已交回',
};
```

侧栏渲染（`BatchBlock.tsx`）：

```tsx
<span className="batch-task-label">{line.label}</span>
<span className="batch-task-status">{STATUS_LABEL[line.status]}</span>
<span className="batch-task-duration">{line.duration}</span>
```

**只有状态 + 耗时，没有"在做什么"。**

**改法**

1. **runtime 侧**：SSE 事件里补当前步骤描述
   - 已有轨迹数据（工具调用记录），从中提取一句话摘要
   - 不必新增数据源

2. **前端**：
   ```tsx
   <span className="batch-task-step">{currentStepLabel}</span>
   ```
   例如"正在修改 App.tsx"、"正在运行测试"

3. **样式**：`.batch-task-step` 用 `--fs-xs` + `--color-label-tertiary`，
   一行截断（`Text truncate`）

**验收**

- 派一个需要 30 秒的任务，观察侧栏是否显示当前步骤
- 10 秒内必须出现第一句有意义的步骤描述
- `pnpm ui:audit` 通过（长步骤名要能截断）

**风险**

如果 runtime 暂时给不出步骤名，**降级为显示"第 N 步"**，也比干等强。

### UD-02 · 思考/工具调用的三层披露

**为什么**

[03 A3/A4/C2](03-agent-ui-problems.md#a3--思考过程暴露太多)：
轨迹页有完整记录（✅），但**摘要层缺失**——用户要么看不到，要么一次看到全部日志。

**现状**

- `TraceView.tsx`：完整工具调用记录，独立视图
- `BatchBlock.tsx`：侧栏一行状态
- 中间层（"改了 3 个文件"这类摘要）**没有**

**改法**

建立三层：

| 层 | 内容 | 在哪 |
| --- | --- | --- |
| 1 | 一句话结论 | 侧栏 Agent 行 / 对话流 |
| 2 | 关键细节（改了哪些文件、几步） | 展开 Agent 行 |
| 3 | 完整轨迹 | 点进 `TraceView` |

**验收**

- 跑一个调用 10+ 次工具的任务，对话流占的行数 ≤ 5 行
- 点开能看到完整轨迹

**复用**

`BatchBlock.tsx` 已有 `ListItem` + 折叠结构，扩展而非重写。

## P1 · 其次

### UD-03 · 从失败步骤重试

**为什么**

[03 B3](03-agent-ui-problems.md#b3--无法单步重试)：现在失败了只能重新派活。

**现状**

有 Agent 续聊（带上下文追问 ✅），但没有"从第 N 步重试"。

**改法**

这是**功能改动**，不只是界面：

1. runtime 需要支持"从检查点恢复"（`snapshots` 已有？需确认）
2. 前端在失败卡片加 [从这一步重试]

**注意**

如果 runtime 不支持，**先不做**——[文档约定](../ui-dev-guide.md)要求：
不能伪造执行进度。同理，不能假装能单步重试。

**验收**

在轨迹里选一步 → 点击重试 → 从该步继续，前面步骤不重复执行。

### UD-04 · 权限级别常驻可见

**为什么**

[03 B4/D3](03-agent-ui-problems.md#b4--自主性一刀切)：用户不知道 Agent 现在能做什么。

来源（[01 原则 12](01-authoritative-guides.md#原则-12逐刻协商能动性)）：

> "让当前自主级别常驻可见。用户应该始终知道 AI 现在被授权做什么。"

**现状**

- `PermissionPicker.tsx` 在输入区可以选择权限（四档）
- 但**运行中的 Agent 用什么权限，界面上看不到**

**改法**

在 Agent 行或会话头部显示当前权限徽标：

```
[读写 · 需审批]  正在修改 App.tsx
```

**验收**

改了权限后，徽标立即变化；看得出"这个 Agent 现在能不能删文件"。

### UD-06 · 失败信息三要素

**为什么**

[03 D2](03-agent-ui-problems.md#d2--失败时只说出错了)：只说"出错了"不够。

**现状**

有 `errorDisplay.ts` + `ERROR_KIND_LABEL`（✅ 分类）。

**缺的是三要素中的后两项**：

| 要素 | 现状 |
| --- | --- |
| 发生了什么 | ✅ 有 |
| **保留了什么** | ❌ 没有 |
| **怎么重试** | ❌ 没有 |

**改法**

失败卡片补两行：

```
[发生了什么] TypeScript 编译失败：Login.tsx:42
[保留了什么] 已完成的 3 个文件改动已保存
[怎么重试]   [重试] [查看日志] [跳过]
```

**验收**

制造一次失败，检查三要素齐全。

### UD-08 · 上翻时冻结自动滚动

**为什么**

[03 E2](03-agent-ui-problems.md#e2--流式输出强行拽回底部)：用户看历史时被拽回底部。

**现状**

`Conversation.tsx` 有 `scroll.atBottom` 和 `scrollToBottom`，
已有跟随逻辑（skill ENG-11 的要求）。

**需要确认的是**：

- 用户向上滚动时，`atBottom` 是否正确变为 false
- 流式新内容到达时是否真的冻结

**改法**

如果已实现 → 补测试；如果没实现 → 按 ENG-11 的逻辑补。

**验收**

- 运行中向上滚动到历史，等新内容到达，**页面不跳**
- 滚回底部后恢复跟随

### UD-05 · 高影响动作首次提示

**为什么**

[03 B5](03-agent-ui-problems.md#b5--同意是一次性的)

**改法**

某个高影响动作（删除/推送/发布）**首次**执行时，
在审批卡片上加一句说明它意味着什么。之后不再重复。

**注意**

不要做成"每次都要多点一次"——那是骚扰。

### UD-07 · 支持减少动效

**为什么**

[03 E1](03-agent-ui-problems.md#e1--长循环动画累人)，WCAG 2.3.3

**改法**

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

对思考态动效尤其重要（长时间循环最累人）。

---

### UD-09 · 状态过渡统一用令牌

**为什么**

[03 E3](03-agent-ui-problems.md#e3--状态切换生硬)

**改法**

检查 `styles.css` 里所有 `transition`，把写死的时长换成 `--dur-fast/base/slow`。

**验证**

```bash
grep -oE 'transition[^;]*[0-9]+\.[0-9]+s' apps/web/src/styles.css
```
应该为空。

---

### UD-10 · 数字等宽

**为什么**

[03 E4](03-agent-ui-problems.md#e4--数字跳动导致横向震颤)

**改法**

所有动态数字的位置加：

```css
font-variant-numeric: tabular-nums;
```

主要位置：token 数、耗时、计数徽标、进度。

**验证**

数字从 9 变 10、999 变 1000，宽度不应变化。

## 不做的事

| 不做 | 理由 |
| --- | --- |
| 改成 L4 全自主 | 本项目定位是"人拍板"，[01 §1.4](01-authoritative-guides.md#14-对-opencoxswain-的直接映射)分析过 |
| 加进度百分比 | 系统不知道还要多久，编数字是欺骗 |
| 把轨迹塞进对话流 | 已经分离了，别倒回去 |
| 照抄 Perplexity 视觉 | 只抄模式，不抄皮肤 |

## 与 ui-dev-guide 打磨项的关系

[ui-dev-guide](../ui-dev-guide.md) 的 P0 是**CSS 结构问题**（行高 15 种、`.md-body` 27 条规则）。

这章是 **Agent 交互问题**（状态、控制、披露）。

**两者不冲突，可以并行**，但建议：

1. 先做 ui-dev-guide 的 **P0 #1（行高收敛）**——它影响全站，且是后续所有视觉改动的基础
2. 再做 UD-01 / UD-02——它们需要在干净的基础之上
