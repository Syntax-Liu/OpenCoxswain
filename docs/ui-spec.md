# 界面规范

> **这份文档是界面开发的唯一标准。改界面之前先读它，不要在对话里再确认一遍。**
>
> 写于 2026-11-12。后续所有界面改动都必须符合本规范；
> 如果必须偏离，先改这份文档并说明理由。

## 三、尺寸与排版

| 项 | 值 |
| --- | --- |
| 控件圆角 | 2–3px（`--radius`） |
| 输入框/面板圆角 | 6px |
| 消息气泡圆角 | 12px |
| 正文 | 13px / 行高 1.5 |
| 次要文字 | 11–12px |
| 侧栏行高 | 20px |
| 内容最大宽度 | 820px，居中 |

**密度要高**。桌面软件不是手机 App：
- 行高紧凑
- 留白克制
- 不要大圆角、不要大色块

## 四、布局骨架

```
┌─────────────────────────────────────────────────┐
│ OpenCoxswain  路径              − □ ×           │ ← 自绘标题栏 30px
├──────────┬──────────────────────────────────────┤
│ [⊕ 新会话]│ 项目名  [Agent 模式]          路径    │
│ ◎ Supervisor│ 对话  轨迹  ⋯                     │ ← 标签页 34px
│ ⊞ 添加项目│ ─────────────────────────────────    │
│ 工作区 🔍⇅＋│ 消息区（自己的滚动容器）             │
│ ▾ 项目    │                                      │
│   会话 完成│ ┌──────────────────────────┐        │
│          │ │ 发消息或创建任务…          │        │ ← 输入框
│          │ │ 用模板 停止            (↑)│        │
│          │ └──────────────────────────┘        │
│ ●已连接 设置│        右对齐状态栏                 │
└──────────┴──────────────────────────────────────┘
```

### 侧栏

- 顶部：**新会话**大按钮（占满宽度）
- 功能项：图标 + 文字（Supervisor / 添加项目）
- 工作区标题行：文字 + 右侧图标组
- 项目可折叠：**箭头负责折叠，名字负责进入**（拆成两个按钮）
- 会话项：标题 + 右侧状态（右对齐）
- 底部：连接状态 + 设置
- 右边缘 5px 拖拽把手

### 主区

- 标题行：项目名 + 徽章 + 路径
- 标签页：对话 / 轨迹（可点，选中只变字重）
- 消息区：独立滚动，内容限宽 820px 居中
- 输入区：圆角框，内含工具栏 + 圆形发送按钮
- 底部状态栏：右对齐的指标

## 五、交互约定

| 场景 | 做法 |
| --- | --- |
| 搜索 | 收起态是放大镜，点击展开成输入框，自动聚焦；`Esc` 或 `×` 关闭 |
| 项目折叠 | 箭头折叠，名字进入（两个按钮） |
| 会话操作 | 右键菜单：打开 / 复制 ID / 删除 |
| 危险操作 | 删除类用红色；运行中禁止删除并说明原因 |
| 焦点态 | 只变边框颜色，**不要整圈 outline**（会和边框形成双线） |
| 失败反馈 | **必须可见**，不能只写 console |

### 禁止事项

- ❌ 系统原生右键菜单（WebView2 的"返回/刷新/另存为"）——壳层已注入脚本拦截
- ❌ 大圆角（≥8px 用于控件）
- ❌ 浅色背景块 + 纯白图标（在深色界面上像贴纸）
- ❌ 圆形头像（用一行小字角色标签代替）
- ❌ 用户消息上标"你"（自己说的话不需要标注）
- ❌ 写死像素值而不走令牌

## 六、文案规范

| 规则 | 说明 |
| --- | --- |
| 术语用英文 | User / Supervisor / Assistant / Agent，中文不翻译 |
| 首字母大写 | `Supervisor` 不是 `supervisor` |
| 不要 Markdown 语法 | 纯文本里不要出现 `**bold**` |
| 错误信息说人话 | 讲清"哪里不对"和"该怎么办" |

## 七、开发流程（重要）

改界面时必须按这个顺序，否则会返工：

1. **先读本文档**，确认要改的部分属于哪个区域
2. **查真实数值**（DSH 源码 / VS Code 令牌），不要估
3. 改代码
4. **真实截图验证**——用 CDP 打开页面截图，不要只看编译通过
5. 检查是否偏离规范；偏离就修，或者先改规范并说明理由

### 验证工具

```bash
# 启动应用
apps\shell\src-tauri\target\release\opencoxswain.exe

# 用 Chrome CDP 连上去检查 DOM / 截图（见 .shot.mjs 模板）
# 不要用 Invoke-WebRequest 截图——那抓不到真实渲染
```

**教训**：出现过三次"编译过了、接口返回 200，但用户点了没反应"。
原因是只验证了代码，没验证**用户的实际路径**。
