## 三、做完 ≠ 没问题

这些是**有意保留**的取舍，不是遗漏：

| 项 | 状态 | 为什么这样 |
| --- | --- | --- |
| 沙箱 | 静态检查，非进程隔离 | 真隔离要原生模块，破坏零依赖 |
| 沙箱挡不住的 | 运行时才算出路径、脚本内部行为 | 靠审批 + 只读档兜底 |
| 代码导航 | 词法级，非真 LSP | 零依赖、零配置，任何语言可用 |
| 搜索 | LIKE，非 FTS5 | 当前量级毫秒级，不值得提前付复杂度 |
| 上下文压缩 | 不调模型做摘要 | 摘要要额外调用，出错会把正常运行变成失败 |
| 撤销 | 只做文件写入 | 命令执行撤不了，不假装 |

**这些都写进了各自的文档，并说清了边界。**

## 五、现在该不该收尾

**代码可以收，验证不能收。**

理由：这 15+ 项里有 **6 个 bug 是"类型检查通过、测试全绿、功能就是不工作"**：

| Bug | 后果 |
| --- | --- |
| 沙箱只查命令名，漏了 shell 重定向 | **沙箱等于没生效** |
| 附件 images 在四层链路各漏一处 | 图片入库前就丢了 |
| `/api/search` 路由插错块 | 永远 404 |
| 引导只在空对话显示 | 老用户永远看不到 |
| 快照传参漏了 `runExecutor` 那一环 | 撤销一直不生效 |
| 批次位置按时间贴标签，显示是倒序 | 圆点位置全错 |

**每一个都靠"真实跑一遍"发现的，测试一个都没抓到。**

所以：

> 装上 v0.48.1，用一段时间真实任务。
> 遇到问题按具体现象改，比继续按清单推进更有价值。

## 六、如果用出了问题

按这个顺序排查：

1. **看轨迹**：`轨迹` 标签页有每一步的工具调用和结果，还能按「只看失败」筛
2. **看副作用台账**：它到底改了什么文件、跑了什么命令，可撤销的能直接撤
3. **看状态栏**：上下文用量、轮次步数、缓存命中
4. **看文档**：`docs/` 下每个功能都有边界说明

出了问题把**轨迹里的具体现象**贴出来，比描述"它不好用"有效得多。
