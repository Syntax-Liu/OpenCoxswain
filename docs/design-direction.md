## 一、产品语境探索

设计之前先看清这个产品在什么世界里。以下概念来自代码本身，不是臆想。

### 1.1 Domain（领域词汇）

| 概念 | 在代码里的位置 | 说明 |
| --- | --- | --- |
| **指挥** | `orchestrator.ts` | 产品名 OpenCoxswain 即「舵手」，核心动作是发令 |
| **派遣** | `spawn()` | 一句话派出多个 Agent 同时干活 |
| **回报** | `recordReport()` | 谁先完成谁先报，不等别人 |
| **审计** | `security/ledger.ts`、轨迹页 | 改了什么都留痕，事后可查 |
| **许可** | `settings/permission.ts` | 四档权限 + 危险动作审批 |
| **边境** | `global/cross-project.ts` | 写域互斥、跨项目冲突——谁的地盘 |
| **航行记录** | `TraceView` | 438 条记录、23 小时跨度 |
| **批次** | 并发派活 | 一批同时出发，各自独立回来 |

**关键判断**：这不是聊天软件，是**任务指挥软件**。对话只是下达指令的形式。

### 1.2 Color world（这个领域天然的颜色）

不是"我想要什么色"，是产品所在世界里本来就有的：

| 来源 | 颜色 |
| --- | --- |
| 夜航驾驶台 | 深灰蓝底、**琥珀光**（保留夜视能力的暖光） |
| 雷达屏 | 深墨绿底、青绿扫描线 |
| 航海图 | 米黄纸、赭石海岸线、普鲁士蓝深水 |
| 仪表盘 | 磨砂黑、黄铜刻度、哑光表盘 |
| 调度中心大屏 | 深灰底 + 红/黄/绿状态块 |
| 航行日志 | 泛黄横线纸、蓝黑墨水 |

**共性**：深色底、低饱和功能色、**极少数高亮时刻**。

### 1.3 Signature（只能属于这个产品的元素）

现有界面有一个别处没有的机制：**谁先完成谁先汇报**。

**签名元素：批次线（Batch Line）**

```
你  重构登录页，顺便补测试
── 03:14 派出 3 个 ──────────────────
   ● 查依赖漏洞        完成  0:51      ← 先回来的在上
   ● 重构登录页        进行中 2:14
   ● 补测试            排队
```

**为什么是它**：把产品最核心的机制（并发派活 + 先完成先报）变成看得见的结构。
DSH、VS Code、ChatGPT 都没有这个。

### 1.4 Defaults（必须躲开的默认）

| 默认选择 | 为什么是默认 | 替代 |
| --- | --- | --- |
| **VS Code 冷灰**（#1f1f1f / #0078d4） | 因为"VS Code 好看"就抄了 | 换成本产品的色温（见方向） |
| **消息气泡流水账** | 所有 AI 软件都这样 | **批次结构**：消息按派出批次分组 |
| **侧栏 = 文件树** | 抄 DSH / VS Code | **值班表**：按状态分组（在跑/等你/已完成） |

## 二、三个候选方向

三个方向的**布局完全相同**（DSH 结构），差别只在温度、密度与表达方式。
差别刻意做小——因为布局已经定了，真正要选的是"这个软件什么气质"。

### A · 夜幕指挥台（推荐）

| 项 | 值 |
| --- | --- |
| 底色 | `#0a0c0f`（比 VS Code 更深、偏冷蓝） |
| 面板 | `#11151a` |
| 强调色 | **琥珀 `#e0a04a`** |
| 成功 | 暗青绿 `#5a8f7b` |

**气质**：像夜航驾驶台——暗到只剩必要的光，琥珀是唯一的高亮。

**为什么适合**：
- **长时间盯着不累**。这个产品的使用场景是"派活 → 等 → 看结果"，
  用户会长时间停留，深色底 + 单一暖色高亮疲劳度最低。
- **状态色有意义**。琥珀=进行中（像仪表盘指针）、青绿=完成、暗红=需要你介入。
  不是随便找的配色，是仪表语言的移植。
- **和产品名呼应**。舵手 → 夜航 → 暗底琥珀，一眼能感觉到这是"操控台"。

### B · 航海图鉴

| 项 | 值 |
| --- | --- |
| 底色 | `#14161a`（暖中性灰） |
| 强调色 | **砖红 `#c25a4a`** |

**气质**：像摊开的海图——纸感、克制、有年代。

**问题**：砖红在深色底上容易读成"错误/危险"，而它要表示的是"当前"。
状态色和强调色会打架。

### C · 雷达室

| 项 | 值 |
| --- | --- |
| 底色 | `#0b1110`（墨绿） |
| 强调色 | **荧光青绿 `#4fd1a5`** |

**气质**：雷达屏，状态一目了然，密集但不吵。

**问题**：绿色在通用认知里是"成功"，用它当强调色会让"进行中"和"已完成"分不清。
而且荧光绿长时间看容易疲劳。

## 三、推荐：A · 夜幕指挥台

### 3.1 完整令牌

```css
/* 背景层次：只有一个色相，只变明度 */
--bg:            #0a0c0f;   /* 画布 */
--bg-panel:      #11151a;   /* 面板（侧栏、输入区） */
--bg-elevated:   #171c23;   /* 抬起的元素（卡片、气泡） */
--bg-input:      #0e1216;   /* 输入框（比画布更深，表达"凹陷"） */
--bg-hover:      #1a2028;
--bg-active:     #1f262f;

/* 边框：低透明度，几乎看不见但有结构 */
--line:          rgba(255,255,255,.06);
--line-strong:   rgba(255,255,255,.11);

/* 文字四级 */
--fg:            #c4cbd3;   /* 正文 */
--fg-strong:     #e8eaed;   /* 标题、关键值 */
--fg-muted:      #7a828b;   /* 次要 */
--fg-dim:        #545c65;   /* 元信息、禁用 */

/* 功能色：全部低饱和 + 只有一个高亮 */
--accent:        #e0a04a;   /* 琥珀：进行中、当前、主要动作 */
--ok:            #5a8f7b;   /* 暗青绿：完成 */
--warn:          #c98b4b;   /* 接近琥珀但更暖：需要留意 */
--danger:        #b85450;   /* 暗红：需要你介入、破坏性操作 */

/* 尺寸 */
--radius:        3px;
--radius-lg:     6px;
--font:          -apple-system, 'Segoe UI', 'Microsoft YaHei UI', sans-serif;
--mono:          'Cascadia Code', 'Cascadia Mono', Consolas, monospace;
```

### 3.2 层级与密度

| 项 | 值 | 理由 |
| --- | --- | --- |
| 正文字号 | 13px | 与当前一致，中文在 13px 下清晰 |
| 行高 | 1.5 | 中英混排需要 |
| 侧栏行高 | 20px | 紧凑 |
| 消息间距 | 14px | 呼吸但不松散 |
| 内容最大宽 | 820px 居中 | 一行太长读着累 |
| 侧栏宽度 | 244px，可拖 180–420 | 沿用 DSH 实测值 |

### 3.3 签名元素：批次线的具体规格

```
你  重构登录页，顺便补测试
                          
══ 03:14 · 派出 3 个 ═══════════════════════

 ● 查依赖漏洞              完成    0:51
 ● 重构登录页              进行中  2:14
 ○ 补测试                  排队      —
```

| 元素 | 做法 |
| --- | --- |
| 批次头 | 左右各一条 1px 线，中间琥珀色时间 + 计数，`11px` |
| 任务点 | 实心=完成（青绿）、脉冲=进行中（琥珀）、空心=排队（灰） |
| 任务行 | 单行：点 + 标题（省略）+ 状态 + 时长（等宽数字） |
| 排序 | **完成的排前面**——体现"谁先完成谁先报" |

### 3.4 侧栏改为"值班表"

不再按项目折叠成文件树，而是按**状态**分组：

```
值班
  登录页重构        进行中
  依赖审计          等你决定  ●
  补测试            排队

已完成
  OpenCoxswain.txt  0:51
  初始化仓库        1:02
```

**为什么**：这个产品里用户最关心的是"现在有什么在跑、什么在等我"，
而不是"这个项目下有哪些会话"。文件树是编辑器的思维，值班表是指挥台的思维。

> ⚠️ 这一条改动较大。如果保留文件树也没问题，只是它更像编辑器而不像指挥台。

### 3.5 焦点态与动效

| 项 | 做法 |
| --- | --- |
| 输入框聚焦 | 边框变琥珀，**不加 outline**，背景微微提亮 |
| 按钮按下 | `scale(0.97)`，120ms |
| 面板出现 | 从触发器位置 `scale(0.96)` + 淡入，180ms，`cubic-bezier(0.23,1,0.32,1)` |
| 进行中脉冲 | 2s 循环，只变透明度 |
| 减少动效 | 尊重 `prefers-reduced-motion` |

## 四、实施计划

确认方向后按这个顺序，每步都能单独验证：

| 步骤 | 内容 | 风险 |
| --- | --- | --- |
| 1 | 换令牌（颜色 + 圆角） | 低——只改 CSS 变量 |
| 2 | 批次线组件 + 消息流分组 | 中——需要后端批次信息 |
| 3 | 侧栏改值班表 | 中——交互变化 |
| 4 | 焦点态、动效、细节打磨 | 低 |

**建议先做第 1 步**：只换颜色，立刻能看到整体气质变化，
不满意随时退回（改几个变量而已）。
