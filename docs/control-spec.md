## 零、为什么要有这份文档

用户反馈"UI 很别扭，别扭的地方特别多"。

**盘点后找到了量化证据**——同一屏里：

| 属性 | 实际用到 | 问题 |
| --- | --- | --- |
| 圆角 | 0 / 2 / 3 / 4 / 6 / 10 / 12px + 50% | **8 种尺度** |
| 字号 | 11 / 11.5 / 12 / 12.5 / 13 / 14 / 15px | **7 种**，还有半像素 |

**这不是审美问题，是没有尺度。** 每个控件被单独调过，互不参照。

这份文档定死**所有尺度**。以后改界面只许用这里的值。

## 一、尺度表

### 字号（4 档，不许中间值）

| Token | 值 | 用在哪 |
| --- | --- | --- |
| `--fs-xs` | **11px** | 角标、时间戳、极简辅助文字 |
| `--fs-sm` | **12px** | 次要信息、行内代码、按钮小字 |
| `--fs-md` | **13px** | **正文默认**、按钮、输入框、列表项 |
| `--fs-lg` | **15px** | 标题（对话头 h2、面板头） |

**删除 11.5px 和 12.5px**——半像素字号在任何屏幕上都会模糊。

### 圆角（3 档）

| Token | 值 | 用在哪 |
| --- | --- | --- |
| `--r-sm` | **3px** | 按钮、标签、输入框、行内代码 |
| `--r-md` | **4px** | 面板、卡片、浮层 |
| `--r-full` | **50%** | 圆形图标按钮 |

**对话气泡从 12px 改成 4px**——VS Code 里没有大圆角的容器，
12px 圆角在紧凑布局里显得"软"，与工具软件的调性冲突。

### 控件高度（3 档）

| Token | 值 | 用在哪 |
| --- | --- | --- |
| `--h-sm` | **22px** | 小按钮、标签、图标按钮 |
| `--h-md` | **26px** | 标准按钮、输入框、tab |
| `--h-lg` | **32px** | 主操作按钮、发送按钮 |

### 间距（4px 网格）

| Token | 值 |
| --- | --- |
| `--g-1` | 4px |
| `--g-2` | 8px |
| `--g-3` | 12px |
| `--g-4` | 16px |
| `--g-5` | 24px |

**所有 padding / margin / gap 必须是 4 的倍数**（徽标内部等极小值除外，用 2px）。

## 四、执行方式（**已由控件层接管，2026-11-17**）

### 4.1 现在怎么写界面

**不写 CSS 类，用 `src/ui/` 的组件。** 这是唯一规矩：

```tsx
import {
  Button, DangerButton, TextButton, IconButton,
  ListItem, OptionItem, MenuItem,
  TextInput, Textarea, Field, Select, Text, SendButton, WindowButton,
} from '../ui/index.js';
```

| 要做的事 | 用哪个 | 说明 |
| --- | --- | --- |
| 一般动作 | `Button` | `primary`（一屏一个）/ `secondary` / `ghost` |
| 删除、清空、拒绝 | `DangerButton` | 单独一个组件，名字本身就在警告 |
| 看起来像链接的按钮 | `TextButton` | 「展开更多」「查看全部」 |
| 纯图标 | `IconButton` | **`label` 必填**，缺了编译不过 |
| 列表行 / 导航项 | `ListItem` | 撑满整行、左对齐、`selected` 表示选中 |
| 可选项 / 页签 / 单选组 | `OptionItem` | 一定会带选中态 |
| 右键菜单项 | `MenuItem` | 样式由 `.ctx-menu` 负责 |
| 输入框 | `Field` + `TextInput` / `Textarea` | `Field` 管标签、说明、报错 |
| 下拉 | `Select` | 自绘，不用浏览器原生 `<select>` |
| **一行放不下的文字** | `Text truncate` | 自带截断四件套 |
| 发送键 | `SendButton` | 34×34 正圆，全站同一出处 |
| 窗口按钮 | `WindowButton` | 最小化 / 最大化 / 关闭 |

### 4.2 三件事不许做

1. **不许写裸 `<button>` / `<input>` / `<select>` / `<textarea>`**
   ——`test/uiContract.test.ts` 会扫全仓，出现即测试失败。
2. **不许手写 `btn--*` 类串**
   ——变体与尺寸只能通过组件属性决定。
3. **不许给组件传 `btn--*` 类**（`className`/`variant` 里出现会抛错）
   ——`className` 只用于状态类（`active`）和场景类（`walkthrough`）。

### 4.3 验证

```bash
pnpm test        # 含控件契约、截断覆盖、主题三件套
pnpm ui:audit    # 真实 Chrome：溢出 / 遮挡 / 裁切 / 对比度，任一失败即非 0
```

`pnpm ui:audit` 需要先起服务：

```bash
node apps/runtime/dist/cli.js --serve --static apps/web/dist --port 47911
OCX_URL=http://127.0.0.1:47911/ pnpm ui:audit
```

### 4.4 为什么不是"再加一条 CSS 规矩"

这套规范从 2026-11-13 就写在 `styles.css` 的注释里了，
但那时 UI 里还有 **113 个裸 `<button>`（其中 84 个没走契约）**。
原因很简单：**规矩写在注释里，而写新界面的人手里没有组件可拿**。

现在契约有了组件、有了测试、有了会失败的体检。
文档从"请注意遵守"变成了"不符合就跑不过"。

### 4.5 这次迁移实际改了什么（2026-11-17）

**只换"契约从哪来"，不换样子。** 但顺带修掉了几个真实缺陷：

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 裸 `<button>` | 113 个（84 个不走契约） | **0** |
| 裸 `<input>` / `<textarea>` | 31 个，全部无类名 | **0** |
| 手写 `btn--*` 类串 | 65 处 | **0** |
| `.folder-name` 截断 | 缺 `min-width:0`，长项目名撑破侧栏 | 已补 |
| `.project-picker-name` 截断 | 同上 | 已补 |
| 亮色主题原始色 | 缺 20 个，**弹窗阴影/分隔线/代码块在亮色下变透明** | 已补齐 |
| 元信息文字对比度 | 暗色 3.43:1、亮色 3.46:1（**不达 AA**） | 5.10:1 / 5.36:1 |
| 文字按钮「设置」 | 亮色 3.50:1 | 5.23:1（新增 `--color-action-text`） |
| `styles.css` 乱码注释 | 9 条 U+FFFD，原文不可恢复 | 按下方实际规则重写 |

**没改的**：配色主题、间距尺度、布局结构、字号档位、圆角。
迁移前后截图对照见 `.ui-shots/structure/`。

**不做的事**：不加新颜色、不加阴影层次、不改布局结构。
