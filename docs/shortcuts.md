# 键盘快捷键

> 全局可用，**输入框里也能用**。Esc 按层级关闭：先关命令面板，再关设置。

---

## 键位表

| 快捷键 | 动作 |
| --- | --- |
| `Ctrl+K` | 命令面板（项目 / 动作） |
| `Ctrl+N` | 新对话 |
| `Ctrl+,` | 打开设置 |
| `Ctrl+B` | 折叠 / 展开侧栏 |
| `Ctrl+1…9` | 切换到第 N 个项目 |
| `Esc` | 关闭弹层 / 取消当前操作 |
| `Enter` | 发送（`Shift+Enter` 换行，输入框内） |

Mac 上 `Ctrl` 换成 `⌘`。

设置页 → 通用 → 键盘快捷键 里也能看到这份表。

---

## 命令面板（Ctrl+K）

一个输入框搜一切：

```
项目         opencoxswain      D:\Users\...\OpenCoxswain
动作
             新对话             Ctrl+N
             打开项目…
             打开设置           Ctrl+,
             折叠 / 展开侧栏     Ctrl+B
             打开 Supervisor
```

- 打开时自动聚焦输入框，不用再点一下
- `↑↓` 选择、`Enter` 执行、`Esc` 关闭
- 输入即过滤，匹配名称、说明和分组

## 三条设计规则

### 1. 不和输入框抢键

在 textarea / input 里打字时，**只响应带修饰键的组合**。

所以 `Ctrl+K` 在输入框里也能用，而单按 `/`、`@` 不会被打断——
那些是输入框自己要做的事。

### 2. 不和浏览器抢键

只用 `Ctrl` 组合，避开用户预期由浏览器/系统处理的键：

| 不拦 | 原因 |
| --- | --- |
| `F5` / `Ctrl+R` | 刷新 |
| `Ctrl+W` | 关标签 |
| `Ctrl+C` / `V` | 复制粘贴 |
| `Ctrl+A` / `Z` | 全选、撤销 |
| `Tab` | 焦点导航 |

### 3. Esc 例外

`Esc` **在任何地方都响应**，包括输入框里。

理由：用户在输入框里按 Esc，通常是想关掉弹层，而不是想取消输入。
关闭按层级进行——一次 Esc 只关一层，不会"一按全关"。

---

## 为什么要有命令面板

项目和会话多了之后，靠点侧栏找越来越慢。

命令面板把「用鼠标找」变成「打字找」——这是 VS Code 和 DSH 都有、
而我们之前完全没有的东西。

## 验证记录

用**真实键盘事件**（CDP `Input.dispatchKeyEvent`）验证过，不是只看代码：

```
Ctrl+K  → 命令面板打开，6 条目，分组「项目,动作」，输入框自动聚焦
Esc     → 关闭
Ctrl+B  → 244px → 0px → 244px（折叠再展开）
Ctrl+,  → 设置页打开，Esc 关闭
```

单测覆盖了"不该拦的键一个都没拦"：29 条里有一半是这类**否定断言**
（普通字母、`/`、`@`、`F5`、`Ctrl+W`、`Ctrl+C` 都必须返回 null）。
